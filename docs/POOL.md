# Пул API-ключей

Второй контур доступа. Если подписка недоступна — забанена, не выдана
поставщиком или её срок истёк — запросы обслуживаются пулом оригинальных
ключей Anthropic. Переключение происходит без участия пользователя: диалог,
проекты и память остаются на месте, потому что данные привязаны к аккаунту
Clauden, а не к подписке.

```
аккаунт Clauden ──► подписка (место у поставщика)
                └─► пул ключей Anthropic  ← при бане/сбое места
                        ├─ ключ 1  (активен)
                        ├─ ключ 2  (активен)
                        └─ ключ N  (пауза / отозван)
```

## Что лежит в репозитории

- `backend/src/keypool.mjs` — хранилище ключей, выбор, состояние, паузы
- `backend/src/pool-client.mjs` — вызовы Anthropic Messages с переключением
- `backend/tools/pool-import.mjs` — импорт и осмотр пула
- `backend/scripts/test-pool.mjs` — проверка переключения на мёртвом ключе

Самих ключей в репозитории нет и быть не может.

## Хранение

Ключи лежат в `data/pool/anthropic.json`, зашифрованные AES-256-GCM. Ключ
шифрования — `CLAUDEN_POOL_SECRET`, из него через scrypt выводится 256-битный
ключ с случайной солью. Файл создаётся с правами `0600`.

```bash
export CLAUDEN_POOL_SECRET="…"
node tools/pool-import.mjs add keys.txt production
rm keys.txt
```

`keys.txt` — по одному ключу в строке, формат `sk-ant-…`. Файл с открытыми
ключами после импорта удаляется; в пуле остаются только шифротекст и
отпечатки вида `sk-ant-1…abcd`.

## Переключение

Порядок выбора — least recently used среди активных ключей.

| Ответ провайдера | Что делает пул |
|---|---|
| `401` / `403` | ключ помечается `invalid`, запрос сразу уходит на следующий |
| `429` | пауза 60 секунд, запрос уходит на следующий |
| `5xx`, сеть | пауза 30 секунд, после трёх сбоев — `degraded` |
| `200` | счётчик сбоев обнуляется |

Если ключ умер посреди ответа, поток закрывается, а ход остаётся в журнале:
клиент забирает частичный текст и продолжает тем же запросом — уже на другом
ключе. Пользователь видит один ответ, а не два.

Событие переключения уходит клиенту в потоке как `claude_failover` и
игнорируется интерфейсом; в журнале хода остаётся след.

## Админка

Требуется `x-admin-key`.

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/v1/admin/pool` | состояние пула без самих ключей |
| POST | `/v1/admin/pool/reload` | перечитать файл после импорта |
| POST | `/v1/admin/pool/revive` | вернуть ключ в строй `{id}` |

Ответ `GET /v1/admin/pool`:

```json
{
  "enabled": true,
  "total": 12,
  "active": 10,
  "cooling": 1,
  "invalid": 1,
  "keys": [
    { "id": "key_ab12cd34ef", "label": "production", "state": "active",
      "failures": 0, "cooldownMs": 0, "fingerprint": "sk-ant-1…abcd" }
  ]
}
```

`/health` показывает сводку пула: включён, сколько всего, активных, на паузе
и отозванных.

## Когда пул выручает

- Поставщик не выдал место после оплаты (`account_failed` в заказе).
- Аккаунт подписки забанен на стороне Anthropic.
- У места истёк срок, а продление ещё не пришло.
- У ключа кончился лимит — работает следующий.

Во всех случаях пользователь остаётся в том же аккаунте Clauden: чаты,
проекты, память, настройки — всё на месте, потому что это данные Clauden, а
не Anthropic. Именно поэтому «перевод вместе с переписками» не требует
переноса: переписка и так наша.

## Что видно снаружи

Клиент не получает ни одного ключа и ни одного адреса Anthropic. Он видит
только ответ модели и, при желании, счётчик переключений в журнале хода.
